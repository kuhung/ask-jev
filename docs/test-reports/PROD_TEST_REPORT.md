## 二、测试对象与测试范围

本次测试针对已公开发布在 Vercel 上的生产环境执行：
1. **网络与基础设施层**：HTTPS 证书、HSTS 策略、HTTP/2 协商、404 容错路由、HTTP Method 约束校验。
2. **决策 API 契约层 (`/api/jev`)**：
   - Noul 原语 (Yes/No 二值判断与冲动度计算)
   - Choice 原语 (多项择一、概率分布与置信度)
   - Score 原语 (1 至 10 分加权冲动评估)
   - Context 背景上下文驱动的决策反转能力
3. **输入边界与系统安全性**：空输入、换行纯空格、2000字长文本、XSS 注入标签、SQL 特殊字符、畸形 JSON 数据。
4. **移动端与前端代码走查**：iOS Safari 聚焦防自动放大、中文输入法 Enter 键合成防护、剪贴板复制异常捕获、弹窗交互体验。

## 四、缺陷与优化项清单 (Defect & Improvement Backlog)

按照严重程度分为 P1 (重要体验缺陷) 与 P2 (次要与边界优化)：

### P1 级缺陷 (建议立即排期修复)

#### 1. [P1-DEF-01] Choice 模式末尾问号未剥除产生 `？！` 标点拼接畸变
- **问题位置**：`app/api/jev/route.ts` 中的 `buildTypeSafeRequest` 函数。
- **复现路径**：用户在 Choice 模式提问常规带问号语句，如 `中午吃骨汤麻辣烫还是轻食鸡胸肉沙拉？`。
- **根因分析**：选项分割正则表达式 `question.split(/还是|或者|vs|VS|\/|、/)` 仅按关键词切分，提取出第二个选项为 `轻食鸡胸肉沙拉？`，拼接裁决时代码写为 `首选：${winner}！`，组合生成 `首选：轻食鸡胸肉沙拉？！`。
- **修复方案**：切分后对每个选项字符串剔除首尾的中英文标点（`replace(/^[？?！!。，,\s]+|[？?！!。，,\s]+$/g, '')`）。

#### 2. [P1-DEF-02] Yes/No 否定文案全量硬编码为消费类措辞，导致社交与情感场景严重错位
- **问题位置**：`app/api/jev/route.ts` 中的 `parseTypeSafeResponse` 函数。
- **复现路径**：提问非消费类问题，如 `要不要和前任复合？`、`周五下班部门聚餐去不去？`。
- **根因分析**：代码将 `prob < 0.5` 的否定情况直接硬编码为：
  - `verdict = '坚决别买！'`
  - `reasoning = '...生活里的很多执念买完就贬值。先冷静放上七天，把钱留在兜里带来的安全感更踏实。'`
- **影响后果**：用户咨询情感或社交问题时，老管家给出“坚决别买”、“把钱留在兜里”，破坏沉浸感。
- **修复方案**：参考 `lib/mockJev.ts` 的动词分类器，根据提问中的动词（买/购、去/聚餐/参加、办/充值、复合/找）匹配对应的否定动词（别买、别去、别办、别理）与评语模板。

#### 3. [P1-DEF-03] Choice 模式无分隔符输入降级为机械的 `首选：选项A！`
- **问题位置**：`app/api/jev/route.ts` 的 Choice 降级分支。
- **复现路径**：用户切换到 Choice 模式输入 `中午吃什么？` 或 `周末怎么过？`。
- **根因分析**：未检测到分隔符时，直接塞入 `criteria['选项A']` 与 `criteria['选项B']`，模型判定选项 A 获胜后返回 `首选：选项A！`。
- **修复方案**：未检测到显式候选词时，自动从提问生成两组通俗对立候选（如针对吃什么，默认提供 `重口犒劳 (外卖热食)` 与 `健康轻食 (少油控糖)`），或友好提示用户使用“还是”连接两个具体选项。

### P2 级优化项 (体验提升)

#### 1. [P2-OPT-01] 前端设置弹窗的 localStorage 与 Next.js API 路由参数存在传递断层
- **问题位置**：`components/ApiSettingsModal.tsx` 与 `app/page.tsx`。
- **现状分析**：用户在弹窗中配置了自定义的 TypeSafe API Key 并保存在浏览器的 `localStorage`，但在 `app/page.tsx` 中调用 `/api/jev` 时并未传递该 Key，后端仅从 `process.env.TYPESAFE_JEV_API_KEY` 获取。
- **修复方案**：前端发请求时从 `localStorage` 读取自定义 Key，以 Header (`x-typesafe-key`) 传递给 Next.js 路由代理；若未传递则采用后端环境变量。

#### 2. [P2-OPT-02] 复制金句缺少异步 Promise Rejection 兜底保护
- **问题位置**：`components/VerdictCard.tsx` 中的 `handleCopy` 函数。
- **现状分析**：`navigator.clipboard.writeText(text)` 在非安全上下文（HTTP）或特定内嵌浏览器权限受阻时会产生 Unhandled Promise Rejection。
- **修复方案**：增加 `.catch()` 并在捕获异常时回退到 `document.execCommand('copy')` 机制。

#### 3. [P2-OPT-03] 原生 `alert()` 弹窗影响移动端流畅度
- **问题位置**：`components/VerdictCard.tsx` 的锁定决策按钮、`TopicMatrix.tsx` 的抛硬币提示、`app/page.tsx` 的空值校验。
- **现状分析**：直接调用系统级 `window.alert()` 会挂起浏览器渲染线程，且部分移动端会在弹窗标题显示完整域名。
- **修复方案**：替换为轻量级 Retro 风格的浮层 Toast 或行内提示条。

## 二、表达体系深度剖析与重塑方案 (Expression & Persona)

### 1. 人设表达现状瓶颈

当前老管家 Jev 在接入后端真实 API 后的文案反馈暴露出明显的工程化痕迹：
- **算法语言抢占了角色人设**：
  - 实际输出：`TypeSafe Jev 模型推演显示执行收益明确（概率 77%）。纠结只会徒增心理损耗...`
  - 读者感受：用户看到的是一份算法日志说明，原本 90 年代经典 Ask Jeeves 那种睿智、略带毒舌、见惯世面的绅士管家形象荡然无存。
- **单一模板强行覆盖多元生活语境**：
  - 用户提问 `要不要和前任复合？` 或 `部门聚餐去不去？`。
  - 否定裁决直接输出：`坚决别买！...生活里的很多执念买完就贬值。先冷静放上七天，把钱留在兜里带来的安全感更踏实。`
  - 读者感受：面对情感纠葛和人际往来，管家依然在念叨“别买、把钱留在兜里”，产生了强烈的滑稽感与出戏感。

### 2. 管家人设表达重塑方案

#### ① 角色声音准则 (Voice Guidelines)
- **口吻**：阅尽千帆的老派英式管家，说话一针见血、清醒辛辣，但底色是替主人省心省力。
- **技术信息处理**：模型的胜率、置信度只作为右上角小勋章展示（例如：`胜率 77%`、`冲动预警`），正文评语绝对不以“TypeSafe 模型认为”开头，一律以管家身份直接给出生活洞见。

#### ② 动词意图识别与文案矩阵设计
针对 Yes/No 模式，在后处理层增加动词语义映射，动态生成裁决短语与正文评语：

| 提问场景 | 识别关键词 | 肯定结论 (Yes) | 否定结论 (No) | 否定评语典范 (管家口吻) |
| :--- | :--- | :--- | :--- | :--- |
| **消费大件** | 买、购、换、入、手机、相机 | 果断拿下！ | 坚决别买！ | “你渴望的不是那件物品，是拆快递那一瞬间的虚假掌控感。放进购物车冷冻7天，钱留在卡里比落灰的铁块更有安全感。” |
| **社交聚会** | 去、聚餐、团建、婚礼、饭局 | 盛装赴会！ | 礼貌推掉！ | “凡是去之前就让你心生抗拒的社交，去了也是如坐针毡。消耗两小时周末去迎合尴尬的客套，周一上班加倍疲惫。躺平独处更香。” |
| **付费办卡** | 办、课、年卡、会员、私教 | 放手去练！ | 千万别办！ | “指望用一次性付费来购买自律，是当代人最昂贵的幻觉。先坚持连续两周每晚快走30分钟，真做到了再去谈办卡。” |
| **情感纠葛** | 复合、前任、联系、找他、找她 | 顺从心意！ | 彻底拉黑！ | “吃剩的变质冷饭加热三次也不会变新鲜。现在的不甘心只是沉没成本在作祟。立刻放下手机，去洗把脸睡个好觉。” |
| **闲置处理** | 挂闲鱼、卖、扔、断舍离 | 立刻挂闲鱼！ | 暂且留着！ | “超过大半年没碰过的物件在你的生活里已经死去了。变现成哪怕几十块钱，都比让它白白占用一平米几万块的房间划算。” |

## 三、流程连贯性深度剖析与闭环设计 (User Journey & Flow)

### 1. 当前流程断裂点识别

1. **输入内容与选中模式的不一致**：
   - 用户在输入框敲入 `中午吃骨汤麻辣烫还是轻食沙拉`（明显的二选一语义），但下方单选胶囊依然停留在“是 / 否”模式。
   - 点击 Ask 后，系统返回了 `果断去办！`，回答与提问完全脱节。
2. **灵感抽取时背景信息的暗箱填充**：
   - 首页提供“随便抛个硬币！”灵感功能，点击后随机填充问题与上下文（Context）。
   - 但是输入框下方的“补充具体顾虑”默认是折叠收起的，导致用户看不到被填充进去的背景文字，产生了“为什么只填了标题却影响了模型打分”的疑惑。
3. **裁决操作区的假性闭环**：
   - “听老管家的，就这么办！”点击后仅弹出原生 alert，卡片依然保留原样，没有产生“该决策已被正式封存执行”的完结心理成就感。
   - “我不服再摇一次”针对同一问题再次发起 API 调用时，由于模型输入完全相同，返回概率与文案毫无变化，用户反复点击只会看到一模一样的卡片，失去重掷的趣味。

### 2. 端到端连贯性优化方案

```text
[用户输入或灵感抽取]
       ↓ (自动嗅探：若包含“还是/或者”，自动高亮切换至 Choice 模式)
[模式与背景就绪] (若灵感包含 Context，自动平滑展开背景框，保持透明)
       ↓
[点击 Ask 按钮] (按钮变为“管家审题中...”，平滑滚动锁定卡片锚点)
       ↓
[裁决信封卡片渲染] (呈现醒目结论印章 + 犀利生活点评 + 确切数据标签)
       ↓
[情绪闭环分支操作]
   ├─ ① 听管家的 → 触发撒花粒子 + 卡片加盖“APPROVED 已采纳”火漆印 + 按钮置灰封存
   ├─ ② 我不服再摇 → 若输入未变，管家触发趣味毒舌：“问一千遍老管家也是这句：别买！”
   └─ ③ 复制金句 → 写入剪贴板 + 按钮变为绿勾“已存入剪贴板” (带异常降级机制)
```

## 四、表现形式与视觉美学审查 (Aesthetics & UI Details)

### 1. 设计语言统一化 (Neo-Brutalism 一体化)

- **现状冲突**：
  - 顶部导航条采用了经典 Windows 95/98 的冷灰色立体浮雕（`#808098` / `#5A5A6E`）。
  - 下方内容主体采用了高饱和暖奶黄（`#FAF8D4`）、纯黑粗边框（`border-2 border-black`）与坚硬黑阴影（`shadow-brutal: 4px 4px 0 #000`）。
  - 两者冷暖与粗细反差过大，产生生硬拼接感。
- **重构方案**：
  - 将顶部导航 Tab 彻底重构成 Neo-Brutalism 风格：采用奶黄与黑色粗边框，选中的 Tab 采用经典大红色底（`bg-retroRed-600 text-white`）或纯白底黑色硬阴影，点击时带有 2px 下沉的机械按压反馈。

### 2. 文化符号纯净化 (从东方求签到英式管家文书)

- **现状违和**：
  - 裁决卡片右上角显示 `针对提问：「...」 签号 #8721`。
  - 产品核心形象是西装领结的英国绅士管家（Ask Jeeves），而“签号”属于东方寺庙道观的求签求卦体系，意象发生冲突。
- **重构方案**：
  - 将 `签号 #8721` 调整为 `管家裁决备忘录 No. 8721` 或 `DECISION DISPATCH #8721`。
  - 使用等宽打字机字体（Monospace Courier）排版，增添老式打字机手打文书的庄重感与复古趣味。

### 3. 字体与移动端排版优化

- **评语字体跨平台统一**：
  - 目前裁决评语设置了 `font-serif`。在 Windows 或部分 Android 机型上，缺少优质衬线字体时容易渲染出不美观的系统宋体。
  - 建议建立规范的跨平台衬线字体栈：`font-family: "Songti SC", "Noto Serif CJK SC", "Source Han Serif SC", "SimSun", serif`，确保在各端呈现一致的典雅老管家质感。
- **彻底剔除原生 Alert 弹窗**：
  - 全站 4 处 `window.alert()`（关于管家、广告招租、听老管家的、输入为空校验）全部升级为轻量级 Retro Toast 浮层组件。
  - 浮层采用经典奶黄底、黑粗边框与黑色硬阴影，彻底杜绝移动端浏览器弹窗截断与显示 URL 的破坏性体验。

## 五、分阶段改造实施方案 (Roadmap)

按影响面与落地成本将上述优化拆解为三个实施阶段：

### 第一阶段 (P1)：表达与语义连贯性修复（预计 1 个迭代）
1. 重写 `app/api/jev/route.ts` 的文案生成引擎：剔除“TypeSafe 模型推演显示”等机械表述，建立动词路由字典（买/去/办/复合/闲鱼），提供有温度的管家评语。
2. 修复 Choice 模式标点清洗逻辑，剥除选项末尾中英文标点符号。
3. 增加 Choice 模式无选项输入的启发式管家回复，消除“选项A”机械占位符。

### 第二阶段 (P1)：交互闭环与心流顺畅度改造（预计 1 个迭代）
1. 在 `VerdictCard.tsx` 中增加“已采纳”火漆印印章动效，点击“听老管家的”后卡片进入锁定态。
2. 在 `DecisionBox.tsx` 中，灵感填充 context 时自动展开背景输入框，确保背景可见。
3. 对同一问题重复点击“不服再摇”时，注入管家趣味敲黑板提示。

### 第三阶段 (P2)：视觉美学与设计系统统一（预计 1 个迭代）
1. 顶部 Tab 导航彻底收敛为 Neo-Brutalism 粗黑阴影风格，消解冷灰 Windows 98 拼贴感。
2. 全局原生 `alert()` 升级为 Retro Toast 浮层。
3. 文化意象统一：将“签号”替换为“管家备忘录编号”。
